## Что такое сокет?

**Сокет** - это программный интерфейс (endpoint) для сетевого взаимодействия между программами. Представьте сокет как "дверь" или "окно", через которое программы могут отправлять и получать данные по сети.

### Простая схема

```
СЕРВЕР                          КЛИЕНТ
┌─────────────┐                ┌─────────────┐
│  Программа  │                │  Программа  │
│   (Server)  │                │  (Browser)  │
└──────┬──────┘                └──────┬──────┘
       │                              │
       │  Сокет (fd=3)                │  Сокет (fd=8)
       │  127.0.0.1:8080              │  192.168.1.5:54321
       │  [Слушающий]                 │  [Клиентский]
       │                              │
       │◄─────────────────────────────┤ connect()
       │                              │
       │  accept() → новый fd=5       │
       │                              │
       │  Сокет (fd=5)                │  Сокет (fd=8)
       │  [Клиентский]                │  [Клиентский]
       │                              │
       │◄─────────────────────────────┤ send("GET / HTTP/1.1")
       │  recv()                      │
       │                              │
       │─────────────────────────────►│ send("HTTP/1.1 200 OK")
       │  send()                      │  recv()
       │                              │
       │  close(fd=5)                 │  close(fd=8)
       │                              │
       │  Сокет (fd=3)                │
       │  [Слушающий] ← продолжает слушать
       │
```

### Ключевые понятия

1. **Сокет** = файловый дескриптор + адрес (IP:порт)
2. **Слушающий сокет** = ждет новых подключений (один на порт)
3. **Клиентский сокет** = подключение к конкретному клиенту (много одновременно)
4. **Файловый дескриптор (fd)** = число для работы с сокетом (3, 4, 5, ...)

### Аналогия с телефоном

- **Сокет** = телефонный аппарат
- **IP-адрес** = номер телефона (например, 127.0.0.1)
- **Порт** = внутренний номер в офисе (например, 8080)
- **bind()** = настройка телефона на конкретный номер
- **listen()** = включение режима ожидания звонков
- **accept()** = принятие входящего звонка
- **recv()/send()** = разговор по телефону

### Что такое сокет на системном уровне?

1. **Файловый дескриптор (file descriptor, fd):**

   **Что это такое:**
   - В Unix/Linux сокет представлен как файловый дескриптор — целое число (например, 3, 4, 5)
   - Файловый дескриптор — это "ручка" (handle) для доступа к ресурсу операционной системы
   - Это идентификатор, который ядро ОС возвращает программе при создании ресурса

   **Что означает "идентификатор, который ядро ОС возвращает программе":**

   Когда вы вызываете системный вызов (например, `socket()`, `open()`, `pipe()`), происходит следующее:

   1. **Ваша программа** вызывает функцию (например, `socket()`)
   2. **Функция делает системный вызов** — переходит в режим ядра (kernel mode)
   3. **Ядро ОС** создает внутреннюю структуру данных для ресурса в своей памяти:
      - Для сокета: создает структуру с буферами, состоянием, адресом и т.д.
      - Для файла: создает структуру с информацией о файле, позицией чтения и т.д.
   4. **Ядро выделяет номер** (идентификатор) из таблицы файловых дескрипторов процесса
   5. **Ядро связывает номер с ресурсом** — записывает в таблицу процесса указатель на созданную структуру
   6. **Ядро возвращает номер программе** — функция возвращает это число (например, 3)

   **Почему это важно:**

   - **Разделение ответственности**: Ресурс живет в памяти ядра (защищенная область), а программа получает только "номерок"
   - **Безопасность**: Программа не может напрямую обращаться к структурам ядра, только через системные вызовы
   - **Управление**: Ядро контролирует все ресурсы и может проверять права доступа
   - **Абстракция**: Программе не нужно знать детали реализации, достаточно знать номер

   **Аналогия:**

   Представьте банковскую ячейку:
   - Вы просите банк (ядро) создать ячейку (ресурс)
   - Банк создает ячейку в хранилище (память ядра)
   - Банк дает вам номер ячейки (файловый дескриптор, например, 3)
   - Вы не можете зайти в хранилище напрямую, но можете использовать номер для операций
   - Когда вы говорите "открой ячейку 3", банк знает, какую именно ячейку открыть

   **В коде это выглядит так:**

   ```cpp
   // Программа вызывает socket()
   int fd = socket(AF_INET, SOCK_STREAM, 0);
   
   // Что происходит внутри:
   // 1. socket() → системный вызов в ядро
   // 2. Ядро создает структуру сокета в своей памяти
   // 3. Ядро находит свободный слот в таблице дескрипторов процесса (например, индекс 3)
   // 4. Ядро записывает: таблица[3] = указатель_на_структуру_сокета
   // 5. socket() возвращает 3
   // 6. Теперь fd = 3, и это число - единственная связь программы с ресурсом
   
   // Дальше все операции используют этот номер:
   bind(fd, ...);    // Ядро: "найди ресурс по номеру 3 и выполни bind"
   listen(fd, ...);   // Ядро: "найди ресурс по номеру 3 и выполни listen"
   close(fd);         // Ядро: "найди ресурс по номеру 3 и удали его"
   ```

   **Философия Unix: "Всё есть файл":**
   - В Unix/Linux многие ресурсы представлены как файлы или файловые дескрипторы:
     - Обычные файлы на диске
     - Каталоги
     - Устройства (принтеры, диски)
     - Сокеты (сетевые соединения)
     - Каналы (pipes)
   - Это позволяет использовать одинаковые системные вызовы (`read`, `write`, `close`) для работы с разными ресурсами

   **Как это работает внутри процесса:**

   ```
   Процесс имеет таблицу файловых дескрипторов:
   
   Индекс | Ресурс
   -------|------------------
   0      | stdin (стандартный ввод)
   1      | stdout (стандартный вывод)
   2      | stderr (стандартная ошибка)
   3      | Сокет (созданный socket())
   4      | Обычный файл (открытый open())
   5      | Другой сокет (принятый accept())
   ...
   ```

   **Что происходит при создании сокета:**

   ```cpp
   int fd = socket(AF_INET, SOCK_STREAM, 0);
   // 1. Программа вызывает socket()
   // 2. Ядро ОС создает внутреннюю структуру данных для сокета в памяти ядра
   // 3. Ядро выделяет свободный файловый дескриптор (например, 3)
   // 4. Ядро связывает этот дескриптор с созданным сокетом
   // 5. Ядро возвращает число 3 программе
   // 6. Теперь fd = 3 - это "ручка" для работы с этим сокетом
   ```

   **Внутренняя структура в ядре:**

   Когда вы создаете сокет, ядро ОС создает внутреннюю структуру данных, которая содержит:
   - Тип сокета (TCP, UDP)
   - Состояние соединения
   - Буферы для входящих и исходящих данных
   - Адрес и порт (после bind())
   - Флаги (non-blocking, close-on-exec и т.д.)
   - Ссылку на связанный сокет (для TCP)

   Файловый дескриптор — это просто индекс в таблице процесса, который указывает на эту внутреннюю структуру в ядре.

   **Использование файлового дескриптора:**

   ```cpp
   int fd = socket(AF_INET, SOCK_STREAM, 0);  // fd = 3
   
   // Все операции с сокетом используют этот дескриптор:
   bind(fd, ...);           // Привязка к адресу
   listen(fd, ...);         // Начало прослушивания
   int client_fd = accept(fd, ...);  // Принятие соединения (возвращает новый fd = 4)
   recv(fd, buffer, size, 0);        // Чтение данных
   send(fd, data, size, 0);          // Запись данных
   close(fd);                // Закрытие сокета
   ```

   **Сравнение с обычными файлами:**

   ```cpp
   // Работа с обычным файлом:
   int file_fd = open("data.txt", O_RDONLY);  // file_fd = 4
   read(file_fd, buffer, size);
   close(file_fd);
   
   // Работа с сокетом (такой же интерфейс!):
   int socket_fd = socket(AF_INET, SOCK_STREAM, 0);  // socket_fd = 3
   recv(socket_fd, buffer, size, 0);  // или read(socket_fd, ...)
   close(socket_fd);
   ```

   **Важные особенности:**

   - **Уникальность в процессе**: Файловый дескриптор уникален только в рамках одного процесса. Разные процессы могут иметь разные дескрипторы, указывающие на один и тот же сокет (при наследовании через fork()).

   - **Автоматическое закрытие**: При завершении процесса все его файловые дескрипторы автоматически закрываются ядром.

   - **Ограничения**: Каждый процесс имеет ограничение на количество открытых файловых дескрипторов (обычно 1024 или больше, можно проверить через `ulimit -n`).

   - **Небольшие числа**: ОС старается использовать наименьшие доступные числа. После закрытия дескриптора 3, следующий созданный ресурс может получить номер 3.

   **Пример жизненного цикла:**

   ```cpp
   // Программа запускается
   // Дескрипторы 0, 1, 2 уже заняты (stdin, stdout, stderr)
   
   int server_fd = socket(...);  // server_fd = 3
   bind(server_fd, ...);
   listen(server_fd, ...);
   
   while (true) {
       int client_fd = accept(server_fd, ...);  // client_fd = 4, 5, 6...
       // Работа с клиентом
       close(client_fd);  // Дескриптор 4 освобождается
       // Следующий accept() может вернуть 4 снова
   }
   
   close(server_fd);  // Дескриптор 3 освобождается
   ```

   **Проверка файловых дескрипторов:**

   ```bash
   # Посмотреть все открытые файловые дескрипторы процесса:
   ls -l /proc/PID/fd/
   
   # Или в коде:
   # Можно использовать readlink() на /proc/self/fd/N
   ```

2. **Структура sockaddr_in:**
   - Хранит адрес и порт (IP + порт)
   - Например: 127.0.0.1:8080
   - Подробное описание см. в [STRUCTURES.md](STRUCTURES.md#struct-sockaddr_in)

3. **Типы сокетов:**
   - **Слушающий сокет** - ждет входящие подключения
   - **Клиентский сокет** - подключение к серверу или принятое подключение

## Жизненный цикл сокета на сервере

### Шаг 1: Создание сокета

```cpp
int fd = socket(AF_INET, SOCK_STREAM, 0);
// Создает "пустой" сокет, еще не привязанный ни к какому адресу
// AF_INET = IPv4 протокол
// SOCK_STREAM = TCP протокол (надежный, с установкой соединения)
// Возвращает файловый дескриптор (например, fd = 3)
```

**Что происходит:**
- ОС создает структуру данных для сокета
- Выделяет файловый дескриптор
- Сокет существует, но еще не используется

### Шаг 2: Привязка к адресу (bind)

```cpp
struct sockaddr_in addr;
addr.sin_family = AF_INET;
addr.sin_port = htons(8080);        // Порт 8080
addr.sin_addr.s_addr = INADDR_ANY;  // 0.0.0.0 (все интерфейсы)
bind(fd, (struct sockaddr*)&addr, sizeof(addr));
```

**Что происходит:**
- Сокет привязывается к конкретному IP-адресу и порту
- Теперь сокет "слушает" на этом адресе
- Другие программы могут подключиться к этому адресу

**Визуализация:**
```
До bind():
Сокет fd=3: [не привязан] ──┐
                             │ (ничего не слушает)
                             │

После bind():
Сокет fd=3: [127.0.0.1:8080] ──┐
                                │ (слушает на этом адресе)
                                │
                         Клиенты могут подключиться
                         к 127.0.0.1:8080
```

### Шаг 3: Начало прослушивания (listen)

```cpp
listen(fd, 128);
// Переводит сокет в "пассивный" режим
// 128 = размер очереди ожидающих подключений
```

**Что происходит:**
- Сокет переходит в режим ожидания входящих подключений
- ОС создает очередь для ожидающих подключений
- Сокет готов принимать новые подключения через `accept()`

**Визуализация:**
```
Слушающий сокет fd=3:
┌─────────────────────────────────────┐
│ Сокет: 127.0.0.1:8080              │
│ Статус: LISTENING (слушает)        │
│ Очередь: [пусто]                   │
└─────────────────────────────────────┘
         │
         │ (ждет подключений)
         │
```

### Шаг 4: Принятие подключения (accept)

```cpp
int client_fd = accept(fd, NULL, NULL);
// Когда клиент подключается, accept() создает НОВЫЙ сокет
// для общения с этим конкретным клиентом
// Возвращает новый файловый дескриптор (например, client_fd = 5)
```

**Что происходит:**
- Когда клиент подключается к 127.0.0.1:8080, ОС уведомляет программу
- `accept()` создает новый сокет специально для этого клиента
- Старый сокет (fd=3) продолжает слушать новые подключения
- Новый сокет (fd=5) используется для общения с клиентом

**Визуализация:**
```
До accept():
┌─────────────────────────────────────┐
│ Слушающий сокет fd=3               │
│ 127.0.0.1:8080                     │
│ Очередь: [клиент ждет...]          │
└─────────────────────────────────────┘

После accept():
┌─────────────────────────────────────┐
│ Слушающий сокет fd=3               │ ← продолжает слушать
│ 127.0.0.1:8080                     │
│ Очередь: [пусто]                   │
└─────────────────────────────────────┘
         │
         │ (принято подключение)
         │
┌─────────────────────────────────────┐
│ Клиентский сокет fd=5              │ ← новый сокет для клиента
│ Клиент: 192.168.1.100:54321        │
│ Используется для общения с клиентом│
└─────────────────────────────────────┘
```

## Слушающий vs клиентский сокет

### Слушающий сокет

- **Один на порт** - создается один раз при запуске сервера
- **Ждет подключения** - вызывает `accept()` для принятия новых клиентов
- **Не передает данные напрямую** - только принимает подключения
- **Живет постоянно** - существует все время работы сервера

### Клиентский сокет

- **Один на клиента** - создается для каждого нового подключения
- **Передает данные** - используется для `recv()` и `send()`
- **Временный** - закрывается после завершения общения с клиентом
- **Много одновременно** - может быть множество клиентских сокетов

## Файловые дескрипторы

**Файловый дескриптор** - это целое число, которое представляет открытый ресурс в системе:
- Обычный файл: `fd = open("file.txt")` → fd = 3
- Сокет: `fd = socket(...)` → fd = 4
- Pipe: `fd = pipe(...)` → fd = 5

**Важно понимать:**
- Файловый дескриптор - это не сам сокет, а "ручка" для доступа к нему
- Когда вы вызываете `recv(fd, ...)`, система знает, что делать с этим fd
- Закрытие fd (`close(fd)`) освобождает ресурсы

**Пример:**
```cpp
int sock_fd = socket(AF_INET, SOCK_STREAM, 0);  // sock_fd = 3
bind(sock_fd, ...);                              // используем fd=3
listen(sock_fd, 128);                            // используем fd=3

int client_fd = accept(sock_fd, ...);           // client_fd = 5 (новый!)
recv(client_fd, buffer, size, 0);               // читаем из client_fd=5
send(client_fd, data, size, 0);                 // пишем в client_fd=5
close(client_fd);                                // закрываем client_fd=5
// sock_fd=3 все еще открыт и продолжает слушать!
```

## Передача данных

### Отправка данных (send)

```cpp
send(client_fd, "Hello", 5, 0);
```

**Что происходит:**
1. Данные копируются в буфер ядра ОС
2. ОС отправляет данные по сети клиенту
3. Функция возвращает количество отправленных байт

**Визуализация:**
```
Программа:
  send(fd=5, "Hello", 5, 0)
         │
         │ (копирование в буфер ОС)
         ↓
Ядро ОС:
  [Буфер сокета fd=5]
  "Hello"
         │
         │ (отправка по сети)
         ↓
Сеть:
  TCP пакеты с данными "Hello"
         │
         ↓
Клиент получает данные
```

### Получение данных (recv)

```cpp
char buffer[1024];
int bytes = recv(client_fd, buffer, 1024, 0);
```

**Что происходит:**
1. ОС получает данные из сети
2. Данные копируются в буфер ядра
3. `recv()` копирует данные из буфера ядра в буфер программы
4. Функция возвращает количество прочитанных байт

**Визуализация:**
```
Клиент отправляет данные:
  "GET / HTTP/1.1\r\n..."
         │
         │ (по сети)
         ↓
Ядро ОС:
  [Буфер сокета fd=5]
  "GET / HTTP/1.1\r\n..."
         │
         │ (recv() копирует данные)
         ↓
Программа:
  char buffer[1024];
  recv(fd=5, buffer, 1024, 0)
  // buffer теперь содержит "GET / HTTP/1.1\r\n..."
```

## Неблокирующий режим

### Блокирующий режим (по умолчанию)

```cpp
// Блокирующий сокет
recv(fd, buffer, 1024, 0);
// Программа ЗАСТЫВАЕТ здесь, пока не придут данные
// Может ждать секунды, минуты, или даже бесконечно
```

### Неблокирующий режим

```cpp
// Неблокирующий сокет
fcntl(fd, F_SETFL, O_NONBLOCK);
recv(fd, buffer, 1024, 0);
// Если данных нет, функция СРАЗУ возвращает -1
// errno = EAGAIN или EWOULDBLOCK
// Программа НЕ ждет и может делать другую работу
```

**Зачем это нужно?**
- Позволяет обрабатывать множество подключений в одном потоке
- Программа не блокируется на одном клиенте
- Можно использовать `poll()` или `select()` для мониторинга множества сокетов

## Класс Socket в проекте

### В контексте нашего проекта

В классе `Socket`:
- **Слушающий сокет** создается в `Server::init()`
- Хранит файловый дескриптор в `fd_`
- Используется для принятия новых подключений
- Каждый `accept()` создает новый файловый дескриптор для клиента
- Этот новый дескриптор оборачивается в объект `Connection`

**Поток данных:**
```
ConfigParser → ServerConfig (адреса и порты)
    ↓
Server::init() → создает Socket объекты
    ↓
Socket::bind() → привязывает к адресу (создает слушающий сокет)
Socket::listen() → начинает слушать
    ↓
Server::run() → event loop с poll()
    ↓
Новое подключение → Socket::accept() → новый client_fd
    ↓
Connection(client_fd) → обертка вокруг клиентского сокета
    ↓
recv()/send() → общение с клиентом через client_fd
```

### Пример из реального кода

```cpp
// 1. Создание слушающего сокета
Socket* socket = new Socket();
socket->bind("127.0.0.1", 8080);  // Создает сокет, привязывает к адресу
socket->listen(128);               // Начинает слушать
// Теперь socket->getFd() = 3 (например)

// 2. В event loop, когда приходит подключение
int client_fd = socket->accept();  // Возвращает новый fd = 5
// socket->getFd() все еще = 3 (продолжает слушать)

// 3. Создание Connection для клиента
Connection* conn = new Connection(client_fd, "127.0.0.1");
// Connection хранит client_fd = 5

// 4. Общение с клиентом
recv(client_fd, buffer, size, 0);  // Читаем из fd=5
send(client_fd, response, size, 0); // Пишем в fd=5

// 5. Закрытие клиентского соединения
conn->close();  // Закрывает fd=5
// socket->getFd() = 3 все еще открыт и слушает!
```

**Ключевой момент:**
- **Слушающий сокет (fd=3)** живет все время работы сервера
- **Клиентские сокеты (fd=5, 6, 7...)** создаются и уничтожаются для каждого клиента
- Один слушающий сокет может создавать множество клиентских сокетов

### Назначение класса Socket

Класс `Socket` инкапсулирует работу с системными сокетами (socket API). Создает слушающие сокеты для сервера.

### Ключевые методы

- `bind(host, port)` - привязывает сокет к адресу и порту
- `listen(backlog)` - переводит сокет в режим прослушивания
- `accept()` - принимает новое подключение (возвращает файловый дескриптор клиента)
- `setNonBlocking()` - устанавливает неблокирующий режим
- `setCloseOnExec()` - устанавливает флаг FD_CLOEXEC

### Процесс создания слушающего сокета

1. **socket()** - создает TCP сокет (AF_INET, SOCK_STREAM)
2. **setsockopt(SO_REUSEADDR)** - позволяет переиспользовать адрес
3. **setNonBlocking()** - делает сокет неблокирующим (важно для event loop)
4. **bind()** - привязывает к host:port
5. **listen()** - начинает прослушивать входящие подключения

### Важные детали

- Сокет хранит свой файловый дескриптор (`fd_`)
- После `bind()` сокет готов принимать подключения через `accept()`
- Каждый `accept()` возвращает новый файловый дескриптор для клиента

## Резюме

1. **Сокет** - это программный интерфейс для сетевого взаимодействия
2. **Файловый дескриптор** - это число для работы с сокетом
3. **Слушающий сокет** - ждет новых подключений (один на порт)
4. **Клиентский сокет** - используется для общения с конкретным клиентом (много одновременно)
5. **Неблокирующий режим** - позволяет обрабатывать множество подключений в одном потоке
6. Один слушающий сокет может создавать множество клиентских сокетов
7. Передача данных происходит через буферы ядра ОС
